# 连续短剧批量制作与成片剪辑

来源：2026-10-02 E01 实作，31段原片、名义316秒，最终292.333秒、1280×720。这里只提炼制作方法，不把本集人物、修水剧情、段数、模型或秒数当作其他项目默认值。

## 开始批量前确定什么

- 先锁整集因果链：困境的可见证据 → 有依据的选择 → 行动 → 受阻或后果 → 改变 → 本集结果。结尾的新任务从本集结果产生，而非突然换主线。
- 人物先拥有信息，再做决定。能力边界和地方经验都要参与解决问题，避免主角或AI无依据地知道一切。台词应对当下的人和事做回应，少用脱离处境的口号。
- 建立共享的场景方位、角色身份、服装阶段、道具持有人和事件状态。特别区分“尚未成功”“局部试验”“正式成功”；成功后的水流、绿田、完整设施不能提前进入准备镜。
- 模型任务可以包含同场连续表演与内部切镜。跨时代、跨场、明显时间跳跃另开任务；生成任务数、摄影镜头数、最终使用片段数分别记录。
- 共享设定和首帧完成审阅后，独立任务并发提交；局部问题只阻塞受影响镜头。不在未经统一空间和起止状态前盲目全量并发。

## 首帧与动态分别修

实际首帧决定动态起点。演员已经拿着册页，不能再凭空接一本；从床到远处桌面取物，必须留下起身与移动路径。接受首帧后仅协调表演时，修改 `videoPrompt`，保留图片任务和连续性字段。

本项目关键帧构图可用 `continuity.keyframe_directive`；实作中向通用 `imagePrompt` 追加的动态文字未必进入首帧构图路径。它是**需要重新构图时**的入口，不是修视频稿的默认入口：连续性参与图片哈希，改它可能使已就绪图片失效。修图前留原图、任务ID与字段快照。

小型角色同时描述同景深的相对尺寸、位置和是否允许靠近镜头。厘米数与参考图只能约束，不能保证视频中不放大；仍看实际结果。人物三视图用于身份，不作为剧情画面构图。

## 提交与恢复

付费提交前保存 requestId、项目/镜头ID、模型、参数与状态；成功后补 provider ID。超时或未知回执先按 requestId 查询；不能把“本地没收到”当成“供应商没生成”。

区分三类失败：内容校验未提交、明确供应商失败、状态未知。修正第一类后可按接口幂等约定恢复；第二类确认失败原因后留旧回执再重试；第三类查询恢复。参考资产 preparing 不是提示词差，先等参考就绪，不重画全套人物。

本地 range 首帧队列存在项目级运行锁，不能用多个范围调用强行并发。使用队列内部并发；视频独立提交另行控制并发。恢复脚本跳过已完成任务，任务日志与成片文件都保留。

## 按成片剪，不按预算凑

先用每秒接触表找明显身份、姿态、阶段和镜间错误，再对可疑动作接点查看更密实帧或播放。对白区间用ASR辅助定位。正常片段不做无意义重复检查，生成成功或抽帧清楚也不等于完成了人工试听。

可用局部剪辑解决的错误优先剪：本例床上观察后多余站起与下镜坐姿冲突；清淤原片后部提前演到通水。保留前段有效动作，原片不覆盖。若关键信息本身缺失或整个动作错误，不能靠剪掉错误掩盖叙事缺口，需修该段。

对白结束不一定就是切点：取物、反应、行走、试验结果可能仍在推进。删没有新信息的等待，保留有结果的静默动作。不补静帧、循环动作或放慢无关表演凑总时长。

留 `scene/in/out/start/duration/end` 时间线。所有字幕、音乐和标题使用剪辑后的时间；以实际输出文件确认时长，不将计划秒数写作实测值。

## 字幕和声音

1. 对照原台词与实际ASR，校正同音字；实际交换说话顺序或合理新增台词要单独记录，不能仍按旧顺序打字幕。
2. 字符对齐中完全匹配区间保留逐字时间，**不要将整段匹配字符均匀分配到首尾时间**，否则连段内停顿也被平均掉。替换区间的插值只是估计，需要重点查看。
3. 字幕读尾延长时，结束时间截到下一条开始前，避免两句叠在同一位置。最终输出须满足每条 start < end、相邻不重叠。
4. 原生对白、环境声和动作声保留。音乐按工作、失败、结果等叙事段落进入和退出，不默认满铺；低音量不等于已经完成听感验收。Suno候选和选用区间分开留档。

# 分镜源文与发音时间的边界

分场解析同时识别“内景/外景”标题与 Markdown 的“一、二、三”式编号标题，不能把后一种整集当作一场，也不能把正文“一只布鞋”等词误拆成新场。给模型的源文与返回的 `source_text` 都保留段落边界。对白统一为独立一行的 `角色名：「原句」`；动作、字幕、文书上的字另行标注，不与台词压在同一行。否则基于冒号的发音解析会把整段动作当作说话，错误地触发延长镜头与重复模型修订。遇到此类错误先对照批准稿修复格式，重新计算真实对白和独占动作，再决定是否拆镜；不要为了通过检查把动作念出来或硬延长时长。按场保存原始候选，已返回的内容可以就地审阅，不因格式问题重做整集。

## 原生规划候选的审阅与落库

2026-10-02 新集分镜实作：原始模型响应已返回但格式、群演或时间校验未通过时，保留原始响应与错误另存审阅副本。先对照批准正文逐句建立对白台账，修正格式与声源，再把连续的短动作合成表演段。模型最短时长不能让一个两秒反应变成四秒空等；可以在同一明确空间中用前因、动作、结果与反应构成一个完整任务，并另记段内剪辑。无需重新请求整集，更不能把未通过候选当成完成分镜。

单镜不止校对起止数值，还要按真实先后预演：交接物件后才解除原持有人，替手抵稳门板后主角才离开，已出现过的坡道承担运输路线，结果和检验不在现场瞬间跳过。服装状态与道具完成阶段分别记录；完整成品参考不能把旧物或半成品提前变成成品。人物简称必须映射到已登记演员，不能因原文省称把固定师傅换为匿名匠户。

人工编写的新分镜通过正常保存入口，同样使用共享的时长和导演内容检查。同步前留项目快照，同步后回读真实记录，核对台词顺序、场次、时长、资产绑定与媒体任务ID。前端和后端都有内容提醒，应检查实际保存内容；明确写“末帧”、景别、焦距及主光源，避免标题被去掉后正文缺少锚点。修改现有导演稿时只更新 `videoPrompt`，原连续性、图片与任务ID保持不变。

本次审阅结果是7场、56个表演段、359秒规划，原稿73句台词保留且顺序一致；后端共享检查和前端实际审阅函数通过。数字属于本集，不作为默认模板。对白尚未录音，时长是语速与独占动作估算；首帧及实际声画仍须下一阶段审阅，不能把文字检查当作成片验收。
