# 短剧资产审美

先读项目 AGENTS 与资产/视频规范。沿用用户批准的年代、地域、年龄、画风和资产状态；审美改善不改剧情。用户给生成授权时使用项目媒体接口，否则只交提示词。新候选与已批准资产分开，不自动替换跨集绑定。

## 执行

1. 读取实际项目资产，列身份、场合、季节、成长阶段、构造和材质。缺失项标为设计约定或待核查，不伪装史实。
   在 RuoYi Drama 中先查询后台真实《审美》技能，核对项目 aestheticSkillName 绑定及内容版本；导演为独立 directorSkillName。维护使用 docs/style-skills.md 的目录API/后台工作区，不硬编码新选项，也不把个人技能副本冒充实际已加载的项目技能。
2. 先决定可辨识轮廓，再定配色、体积和材质。人物至少区分脸型、年龄、姿态、服装四项；贫困用材料与局部修补表达，不让所有人灰黑泥脸。
3. 古代题材先查适用史料。本次明代见 references/ming-aesthetics.md；不要把本剧颜色、人物或装备固化为所有短剧的规则。公服品色与常服补子分开核查。
4. 按 references/review-and-prompts.md 写独立人物定妆、器物或无人空间母版。静态资产不塞整段动作、多人物和字幕。动态首帧另读导演规范，从已审图的0秒状态展开。
5. GitHub 仅提供渲染组织方法，不能证明服饰史。references/sources.json 记录实际读取程度和许可限制；只提炼方法，不把游戏人物/商用截图当开放素材，不运行外部代码。
6. 保存实际模型、完整提示词、尺寸、资产ID、任务凭据。文生图不保证旧脸一致，不悄悄换编辑模型。未知提交先查任务，不重复付费。
7. 打开实际图片逐项审阅：身份时代、形制、轮廓比例、材质配色、空间结构、手脸细节。模型完成、高分辨率不能代替审图。
8. 展示小批候选供用户确认。选择后再固定跨集身份、衣服与空间；保留退回图和具体理由。

## 维护

仓库技能目录是可版本化源，个人安装为副本。每次只增能改变一个具体判断的资料或案例，记录核查日期、读取程度、身份/年代/地域范围、许可状态、观察与局限。用户反馈保留于项目审阅日志，再提炼可复用规则；单图问题不能升级为通用禁令。

公开网页不代表图像可再分发。争议标明，优先保持身份与可见结构自洽。审美标准需解释为什么选图，不能只堆“精美、电影级、8K”。
