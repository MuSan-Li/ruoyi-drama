# 分镜生成与进度

点击资产配置中的「生成分镜」后立即进入第 4 步。分镜以瀑布流卡片逐步展示：镜头规划草稿、完整场次校验后的规划、细化完成。尚未返回的镜头显示占位卡，不预设模型会生成多少镜头。

进度只出现在第 4 步。生成期间可以查看剧本、资产和其他项目；原项目任务继续运行。刷新页面会查询原请求，显示已返回的卡片和实际阶段，不重新提交生成。

状态区显示已规划与已细化镜数、总用时、当前场次或细化批次、修复次数、模型正文返回量和最近输出时间。模型仅有思考活动时显示活动状态，不展示原始思考正文；后台心跳不能证明模型仍有输出。失去连接时继续查询原请求，不能据此判定失败或自动重试。

草稿与细化卡片供查看；输出可读取且资产引用有效后保存为可编辑分镜；时长、内容和连续性问题作为审阅建议。已有批准图片与视频在其他制作版本中保留。

## 调用与排查

规划先在同一次请求中预演原文动作和对白，按有效内容估时，再安排适合内容的生成段数。不增加用户的时长、镜数设置，也不另请求一次模型预估。说话人切换、情绪反应或动作阶段不单独要求切镜；能同框或连续表达的因果链留在同段。段内摄影切点与视频生成任务分开，原文规模、真实内容容量和叙事节奏共同决定镜数，风格技能负责怎么拍，不负责扩大故事。

参考 Huobao 的“节拍识别—总量锚定—段内摄影”顺序，规划返回先写 `scene_plan`：核心事件、粗估时间和段落安排，再写 `panels`。同一段落中的摄影子镜头写在段内描述中。粗估参考原对白和有效动作，外貌、材料与环境描述不折算为额外播放时间；不套固定8秒下限或2至4个子镜头。摘要和镜数没有强制校验关系。解析同时兼容旧的纯数组，流式展示只读取真正的 `panels`，不会把段落摘要当成已生成镜头。

原生规划中的一个 `panel` 对应一个视频生成段，段内可包含摄影切点。镜数在规划时按原事件、注意中心、对白与动作容量决定，不用总秒数除以段长硬算，也不在生成后按镜数拦截。已有制作版本不会被自动合并。

同一短场景生成2段或4段都可以，判断依据是剧情是否讲清、动作是否连贯、有没有无意义的重复和扩写；这不是所有剧本的数量范围。段落安排与摄影设计仍在同一次请求内完成，不为锁定某个镜数增加独立预规划调用。

`segment_outline.boundary_reason` 说明自然划段的原因：叙事变化、观看重点、表演节奏或对白动作容量。开始姿态、遇到问题、应对、恢复若仍属于一个目标，先在同次规划内合并；环境与外形随主动作呈现，不逐项占用独立段落。这个说明只影响创作，不增加保存拦截条件。

默认技能与项目选中的可编辑技能需要同时核对。运行目录只在技能缺失时初始化，不会用新版内置文件覆盖已有维护内容；本次通过带 `expectedVersion` 的维护接口更新实际绑定的 `cinematic-storyboard`，回读版本和正文，保留原参考资料、首帧可选规则与连续性约定，再同步默认和新安装目录。只修改仓库中的默认正文，会让选中技能继续加载旧的单镜规则。

时间表修订若漏回状态对象，只保留原规划中已有的明确首态和依序记录的状态变化，不推断未知初态，也不覆盖模型明确返回的相反状态；保留审阅建议，不阻止保存。

初版剧本同样保持原事件规模：简单场面不扩成多场完整故事。场次解析覆盖生成器实际输出的“一　地点。时间。”纯文本标题，保留正文与对白顺序。连续性资料保留明确的已知状态；缺少初态或可能跳变时记录建议，不猜补人物状态，也不触发返工。

原生规划仅对无法读取的输出或不可用的绑定重试一次；时长、状态文字、摄影和节奏建议不触发模型返工。已缓存的可用草稿直接继续细化。

失败是明确终态，顶部显示原因、重新生成和关闭提示；未保存草稿收在可展开区域。已返回时长可加总展示当前草稿估算，缺字段时不编造估算。估算不表示视频已经生成或实际时长已经核验。

匿名群演的可见人数明确为0时，不要求填写不存在人物的服饰和位置，也不要求原文安排群演；非零人数和具名素材引用仍按原规则检查。

常规流程为场次规划、镜头细化、数据检查与保存。规划网络输出可使用 `state_delta`：起始镜明确定义全部物理锚点，连续镜由后台继承前镜交镜接点和末态，应用模型明确写出的状态变化；缺少初态时保留草稿供审阅，新增锚点只记录当前已知状态。显式末态保留原文，不用文字差异拒绝保存。场次最多 3 路并行，细化最多 3 批并行、每批最多 8 镜。规划正文中已闭合的镜头对象可先展示草稿；已校验场次立即展示，细化批次完成即填充卡片，无需等待全部场次和批次。

细化只生成景别、运镜、标题、画面描述、视频提示词和首帧提示词。后台保留原规划的首末态、制作估时、资产绑定与剧情字段，忽略模型对这些字段的重复改写。可执行性建议供审阅；空白指令、遗漏或重复镜号等格式问题集中修复一次，通过的镜头保留。

Seed 2.1 Pro `260628` 的流式分镜请求：短小剧本（不超过2000字符）同时发送 `reasoning_effort=none` 与供应商字段 `thinking.type=disabled`，较长剧本使用 `low`；其他模型沿用其配置。仅返回思考活动和隐藏思考正文是客户端展示选项，不等于关闭上游思考。官方文档说明该型号默认启用思考，默认强度为 high，并支持 low 与关闭思考：[深度思考](https://docs.volcengine.com/docs/ark/deep-thinking?lang=zh)。网关是否遵循参数须通过真实请求验证。

当前默认模型为 `deepseek-ai/deepseek-v4.1-flash`，明确关闭思考。剧本、资产分析和分镜共用文字请求策略与事件流解析；资产和分镜共用请求回执、任务查询、断线恢复和结果回读流程。

每次模型调用记录阶段、场次/批次、尝试次数、输入字符数、首次正文时间、最近活动、输出字符数与结束时间。正文字符数不是 token 数；思考活动摘要长度不能代表全部原始思考 token。规划请求回执与进度分别持久化，终态回执绑定保存的镜头 ID 和内容校验值。没有回执或旧实例仍显示处理中时，不能自动重复付费请求。

## 数据检查与创作建议

时长差异、总预算偏差、最短整数秒、接镜文本一致性和导演稿关键词缺项不阻止保存，也不触发模型返工。JSON、场次身份、非空生成指令和实际资产引用仍须可用。恢复草稿通过数据检查后直接继续细化。制作估时保留生成结果，不在保存前强行压缩至15秒。
