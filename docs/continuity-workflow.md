# 剧情连贯性与分阶段制作

## 工作方式

1. 输入创意先生成剧本，停在「剧本打磨」。检查事实、人物目标、因果和每场预计时长。
2. 「保存并分析资产」使用当前编辑后的剧本。确认角色、服装、场景，制作参考图。
3. 分镜按剧本场次依次规划，携带全剧大纲和上一场末镜；提示词每 8 镜细化一次，最多 3 批并行。各批使用已经确定的起止状态，全部完成后统一审阅和落库。
4. 「剧情连贯性审阅」显示总时长和各镜原因、行动、结果、起止状态。信息齐全不等于语义正确，仍需逐镜审阅。
5. 确认后才点击视频生成。真实文字、票据和软件画面使用已有素材在剪辑中插入，不要求视频模型重新绘制。

重新打磨、分析资产或生成分镜前会保存当前剧本。已修改的剧本会将项目标为 `script_changed`，后端拒绝用旧分镜生成视频；重新生成分镜后解除。新分镜整组成功后才以事务替换旧版，失败保留旧版。

## 发现与修正

| 原行为 | 影响 | 修改 |
| --- | --- | --- |
| 一次创建直接完成剧本到分镜 | 未审稿即扩散错误 | 前端创建使用 `scriptOnly`，逐阶段推进 |
| 全剧最多 40 镜 | 长故事被压缩，因果中间过程易丢失 | 按场规划，按场预计时长拆镜 |
| 仅地点变化才切场 | 同地点次日被误认成连续动作 | 同时保留场次边界 |
| 覆盖已有动机和第一帧状态 | 因果、动作和提示词可能不一致 | 保留已有具体内容，只对缺失字段补全 |
| 细化依赖数组下标 | 分批或乱序响应错配 | 按稳定的镜头编号匹配 |
| 生成前删除旧分镜，细化失败继续 | 失败可能留下空白或不完整结果 | 验证完整后事务替换 |
| 连续性字段仅在后台 | 无法在生成前核对 | 展示逐镜因果、状态及可编辑承接信息 |
| 细化阶段只接收年龄和性别 | 提示词可能擅自给角色换装，与参考图冲突 | 传入已编辑的角色形象档案，约束服装、发型、声音出场与后期素材 |
| 首镜未等待完成便继续批量提交 | 下一镜取不到上一镜末帧 | 每镜完成后才提交下一镜；失败、超时或缺少末帧时中止该连续场次 |
| 仅按地点分组生成视频 | 同地点的时间跳跃可能错误沿用末帧 | 使用分场编号和地点共同分组 |
| 不同时间的场景重新独立生图 | 房间结构、门窗位置可能漂移 | 在资产页选择已有场景图作为参考，再生成时间变体 |
| 推理超过 90 秒被判失败，错误统一报 30 分钟 | 正常长请求被中断，难以定位 | 首正文等待 5 分钟并保留心跳，显示真实错误原因 |
| 长任务中途断线要从头生成 | 重复消耗且可能改变已审阅的内容 | Redis 保存每场规划和每批细化断点 7 天，连接中断重试一次；完整落库后清理本项目断点 |

规划断点关联项目、剧本正文、大纲、风格、比例和资产版本。修改这些输入后旧断点不再复用。生成过程中的断点属于草稿，不会将失败任务标成已完成。界面保留中断说明和当前场次，便于再次点击生成继续。

视频串行逻辑采用模拟提供商测试验证。若提供商不返回末帧，会明确停止连续生成；不能据此声称所有视频模型都已支持末帧衔接。视频画面质量须在确认后另行实测。

## 分批生成与动作审阅

资产配置和分镜确认均支持按十镜选择范围，例如第11—20镜；已完成与生成中的视频不会重复提交。资产生成同样保留本批已完成图片，其他批次不重生。

每批先审阅台词时间、关键帧与前后状态。3秒的过渡镜只保留单一可完成动作；已经开盒、放筷、放稳凳子的状态在下一镜延续，不为表现情绪重复动作。人物的自用手机与代管的父亲手机需要区分。门外敲门、开门、跨门槛、室内交谈必须有明确先后关系，不能仅靠场景名称保证空间正确。

模型的生成时长与剪辑时长分开处理。Seedance 2.0 系列遇到短于4秒的剪辑时，申请4秒素材，并要求动作在原定时长内完成；合成仍以分镜预算裁切，不增加剧情时长。提供商明确返回对应任务失败时结束轮询，网络错误与无关响应不当作任务失败。

短镜裁切前须查看动作是否完成，不能只检查文件时长。原片短于预算时拒绝合成，避免静默拉长或黑帧；微小编码尾差按容差处理。无对白镜头的语音识别须启用语音活动检测，避免把环境声识别成虚构台词。
