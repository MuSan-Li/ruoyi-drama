# 视频导演提示词：默认制作规范

普通生成入口的配置、固定格式和整集核对步骤见[分镜格式与整集复现](storyboard-reproduction.md)。

角色声音先在资产页生成/上传样音并选用，分镜保存实际发言人（包含画外声），提交视频时统一注入角色样音与音频编号映射。声音档案属于角色主身份，不随衣装改变；原对白仍以当前镜头为准。操作、模型限制与持久化约定见[角色声音与视频生成](character-voices.md)。

## 首帧可选

首帧不是生成视频的前置条件。可直接使用已批准的角色、场景和道具参考，根据完整导演稿生成视频；不要为批量视频默认额外生成一批首帧。已有首帧可作为可选参考，工作台关闭“使用已有首帧”时保存 `continuityJson.video_use_start_frame: false`，单镜与批量生成都不附带该图，也不附加已审阅首帧的绑定指令。该设置保留已有候选图片和任务编号，不重画图片。未设置沿用已有参考策略，没有有效首帧时仍可生成。

选择使用首帧时才实际审图，并从已审阅画面展开；不用首帧时以已批准的身份、空间、道具和起始构图规划为依据，不把构图规划写成已审阅图片。超过模型参考图数量时明确分配参考预算，保留完整剧情和原资产。`video_reference_include_location: false` 仅省略视频请求的场景参考图，导演稿仍须明确同一实际空间。

## 视频模型与提交恢复

工作台按镜头保存 `continuityJson.video_model`，选项来自后台实际模型目录。单镜、重试和批量生成均读取逐镜选择；批量范围存在不同模型时分别生成。后端在付费提交前核对传入模型与已保存选择，不因超时、失败或目录排序自动切换模型。修改模型选择保留已批准图片、连续性资料和历史视频。查询已有任务以原提交回执中的 `actualModel` 为准。

参考资产处理超时后，可通过项目的 `/image/upload-reference` 上传同一份原图，在分镜连续性中保存 `video_reference_mirrors` 原URL到上传URL的映射。提交保留原资产、原图序号和导演绑定，仅替换传给供应商的图片地址；映射失效或引用了本镜未选用的原图会阻止提交。Mini及2.5参考图按小于30MB校验，其他图片上传仍按10MB校验。上传回执应保留原文件哈希，不能用重新生成图片代替传输副本。

提交超时且没有返回任务编号时，先在供应商历史核对请求正文。找到匹配的编号后，调用 `/storyboard/{id}/video-submissions/{requestId}/resolve?predictionId=...`；后端按原供应商查询并保存编号和状态，不直接把未知提交改成失败。确认失败后使用新UUID重试，原提交记录仍保留。仅找不到记录或查询暂时失败时继续保留未知状态。

若查询接口暂时不可用，但项目所有者已明确确认控制台失败并要求重试，可在恢复请求中提供 `confirmedFailureEvidence`，记录匹配的任务编号、请求正文和实际失败状态。后端将人工核对来源写进原回执，保留原UUID和视频快照。未提供明确核对依据时，查询异常不会解除未知提交锁。

Atlas 明确返回 HTTP 402 且正文恰为 `{"code":402,"msg":"insufficient balance"}` 时，记录为未受理的失败，不虚构任务编号。旧流程留下的未知记录可经项目所有者核对原服务日志后调用 `/storyboard/{id}/video-submissions/{requestId}/confirm-rejection`，提交实际 HTTP 状态、响应正文及包含原 UUID 的日志依据；后端仅释放匹配的本地未知关联。已返回任务编号、5xx、超时或不明确的正文不走此恢复路径。恢复接口不提交新视频，后续按已授权模型使用新 UUID 重试。

## 视频秒数与制作估算

视频秒数默认留空。`durationSeconds` 和 `timing` 保留为制作估算，不自动传给视频模型，也不作为删减原剧情、对白或动作的依据。留空时生成请求省略 `duration` / `seconds`，提示词不附加固定目标秒数或“只使用前几秒”的裁剪指令。

需要指定时长时，在分镜的“视频秒数（可选）”中填写正整数；生成前会先保存，再按 `continuityJson.video_seconds` 的用户值提交。清空输入会移除此字段，恢复模型默认。`-1` 仅在所选模型支持自动时长时使用。平台不强行套用其他模型的最短/最长秒数或自动取整；所选模型仍可能拒绝不支持的值。指定或清空秒数不会重画已审阅首帧。单镜、重新生成、批量生成采用同一规则。

## 连续表演段与剪辑镜头

MiniMax H3 Developer 图生视频使用精确型号 `minimax/h3-developer/image-to-video`。当前接口需要单张起始图，显式视频秒数为4至15秒；画质支持 `480P`、`768P`、`1440p-sr`、`4k-sr`。4K档位是供应商超分，交付时以原始文件探测出的尺寸和时长为准，不宣称原生4K或仅凭请求参数声称实际15秒。模型按起始图自适应画幅，16:9项目需使用横屏起始图；不附带多人物参考、动作视频或声音参考。项目适配发送 `image`、`ratio: adaptive` 和 `prompt_expansion: false`，保留导演稿，不发送其他模型的音频开关；H3自身自动生成音轨，环境音及人声要求写入导演稿，实际成片仍须检查。原始候选与整理后的标准画幅交付版分别留档。

生成任务不必与最终剪辑镜头一一对应。同一空间、同一连续表演可在一个任务内设计多个镜头，按信息变化切换景别、让对白跨反应镜延续。段长仍按当前模型限制和真实内容预算，不能照搬其他平台的30秒候选。跨空间、跨时代时另建表演段，用明确的剪辑接点连接。

承接JSON显式设置`video_reference_mode: "multi_shot"`时，后端附带角色的准确形象图、场景及已绑定道具；选择使用已有首帧时才附带有效的起始关键帧，逐项生成`@imageN`指代。起始帧只约束0秒，后续机位按导演稿执行。没有首帧或关闭首帧参考时，单镜与多镜段都可从已批准资产和构图规划生成。参考选项不表示图片已经视觉验收；实际使用的图片需审图。`editorial_shots`可记录段内镜号、意图、时间范围，视频原片与最终截取片段分别留档。

视频提示词是每个生成任务的执行指令，需要能回答“谁在什么状态下，如何行动、如何回应，观众看到和听到什么，最后停在哪里”。剧情摘要、固定摄影前缀或一组“电影感”形容词不能承担这些信息。

本规范用于新短剧生成与已有分镜修订。场景、服饰、CG能力与时长来自当前项目，不沿用某个试播集的具体设定。核心数字角色应进入人物档案和相应分镜绑定，不能因缺少真人演员而默认只做画外声。

## 编写与审阅

视频提示词按当前镜头提炼技能要点，字数由真实出镜与声源人数、原对白、动作和回应、效果阶段、摄影切点与交镜关系评估。不设统一字数硬上限，不按daily/emotion/action标签套容量，不因字数自动重写、截断或拒绝草稿。先核对必要导演信息，再删除重复措辞；原对白、有效动作、效果结果和声音位置完整保留，历史或人工稿不自动改写。所选供应商有实际输入限制时按该模型校验，不以自定数字代替。

所选审美skill提炼当前画风与必要光色/材质差异，导演skill提炼当前表演、运镜或节奏特点。要点融入具体动作，每项表达一次。已有参考图时省去重复整套外貌衣装，但人物出现时机、持物、接触、受力和空间条件须保留；微动作承担人物意图或因果时仍需展开。删除同义形容词、与本镜无关的禁令、重复锁定声明、下一镜完整剧情与资料来源。时长、分辨率、画幅保存在参数中。

完整默认规范和项目所选技能仍供写作模型规划与审阅；视频提交只发送已保存导演稿一次，再补真实的图片、道具、动作视频及角色音色索引。默认skill全文、所选技能正文、原文动作段、首帧绘图稿、摄影JSON和表演指导不再层层附加；原对白已在导演稿中时不重复发送，确有缺句仅补原话与声源，拆在动作间的同一句对白也视为已写入。技能版本进入任务参数指纹，不写进视频模型正文。单首帧、普通多参考与multi_shot路径遵循同一方式。

因果通顺和画面精美不代表故事好看。爽剧等商业叙事先审主角目标、失败代价、阻力与改变局面的选择，压缩不改变局势的工序；对白按人物意图精修，声音自然度另行试听。相邻片段须有动作/视线接点与实际声桥，适宜场次可短叠化；不把全部硬切换成统一0.3秒转场视为完成。具体做法与反例见[故事、对白与转场](../skills/causal-storyboard-production/references/story-dialogue-transition.md)。保留用户已经认可的画风、人物、字幕和地点介绍。

先读取真实剧本、当前角色/场景、原台词、起止状态和时长预算。选择首帧参考时再读取已审阅首帧，以实际画面继续行动；不用首帧时写清起始构图规划。已有道具或投影不在镜头开头消失后重建。文字与实际使用图片冲突应明确协调；背景参照图不提供剧情动作。

工作台统一使用一个“视频提示词”属性，将摄影、表演、承接和原台词融入连续导演描述，不再单独展示时间预算面板。原文、时长预算、资产引用与连续性仍保留为制作元数据。不要八段固定标题或逐秒清单；按人物动作和对手反应描写实际画面，可用“镜头1/镜头2”组织允许段内剪辑的表演段。检查以下内容，不以固定字数或标题数量判断：

| 内容 | 可执行信息 |
| --- | --- |
| 参考与边界 | 时长、画幅、实际出镜与声源、场景、身份/构图参考各自用途、起始站坐/持物 |
| 镜头与运镜 | 景别、角度、焦点、轴线、一种主要摄影策略及其叙事理由 |
| 动作衔接 | 按动作与对手反应展开，交镜状态可继承；具体时间预算独立存入timing |
| 对白与口型 | 原话、先后、听者闭嘴、画外/心念/CG声源、说完之后的停顿 |
| 光色与材质 | 既有光源方向、演员肤色、衣料/纸/木/玻璃等具体表面；CG是否影响环境 |
| 声音 | 所属空间的环境声、实际动作声、人声距离及配乐意图 |
| 结束与承接 | 实际末帧、角色位置、手中道具、已知信息；下镜意图不提前表演 |
| 局部约束 | 必要禁止项、真实素材和精确文字的后期替换、角色/能力边界 |

工作台默认以阅读排版展示视频提示词：保留已有镜头与段落标题，长段落在引号外的完整句子之间分开，引号内文字与素材编号适度突出。阅读、展开和复制不改写已保存提示词；编辑模式中的“分段排版”只整理换行，支持撤销，点击“保存镜头”后才写入。不会自动添加固定标题、时间段、对白或导演指令，也不修改连续性、素材引用和媒体任务。分镜生成草稿和素材关系图使用同一阅读排版。

只描述本镜实际出场、发声或发生互动的人物与元素。未出场的角色、精灵和投影直接省略，不把“Codex不出现”等排除句套进每镜；下一镜的完整起始画面留在连续性资料中，不复制进本镜生成指令。

细节按信息作用取舍：递物写清接住、炮击写清命中和破坏、对白留下关键回应。空间与光色交代清楚，机位随关注点变化，声音有真实来源；关节、衣料和微表情在影响接触、受力或表演时具体描述，不机械展开，也不因压字数删掉必要信息。不加新事件、慢动作或停顿来凑篇幅。默认业务技能与细化示例同样遵循这些规则。

分镜页移除时长加减、类型/景别/运镜/场景编辑、角色站位栏和修订视频/审阅稿导入入口；机位、场景与站位写入视频提示词，原制作数据和资产绑定保留。顶部工具、音乐创作、参考音频与连贯性审阅区在该页隐藏，保留镜头导航、参考图、视频生成/保存及成片合成。

默认用连续动作描写，时间预算独立记录；不强制正文逐秒列段。4秒静默镜可以是一个完整段，10秒双人对话需要给双方原话和反应留够时间。以实际录音为准；估算时逐句核对所属节拍，而不是只核全镜字数。人物一边说话一边轻微转头属于并行动作；落笔、交纸等占用额外时间的动作另计。

静默不等于没有声音设计。可写呼吸、既有风声或衣料摩擦，不随意添加来电、爆炸等剧情事件。固定镜头不等于没有表演；用视线、指尖、下颌与停顿把人物变化拍出来。

搬运、到位、触发、效果与余波分别交代当前状态。运输镜不提前播放下一阶段的声光效果；效果的可见起点与声响同步，剪辑留住实际触发与后果。被冲击、丢弃或破坏的物件先建立来源与持握状态，沿相同外形继续受力、变形或落地，不在结果镜新造大物件。群演以能感知的刺激先后反应，人物与重物的比例、进退路线和受力姿态需在实帧中成立；壮观布景不能代替压力与空间逻辑。

## 时长与节奏审阅

先按对白、独占动作与必要反应估算节奏。已有录音可用实测，无录音时注明语速估算；表情、视线、运镜可能与对白同时发生，不重复计时。`timing` 是制作参考，`strict_fill` 历史标记不再触发保存或生成拦截。

内容估算13.3秒而安排11秒、实际总长与剧本预计不同、非对白时间较长、没有填写pacing_note，都只作为审阅建议。镜数和段长由原文事件与自然节奏决定，不要求精确总和或最短整数秒，也不为凑数增加剧情。动作完成后是否需要停留，应结合实际画面和声音判断。

接镜文字、状态锚点和摄影声音描述的检查同样只供审阅，不能用逐字相等或关键词命中代替导演判断。生成流程保留能读取、能绑定、能编辑的草稿，内容建议不触发模型反复重写；无法解析的输出、缺失的生成指令和不可用的资产引用才需要修复。实际视频参数仍遵循所选模型接口。

## 项目默认接入

- 后端 `ShortDramaDirectorSkills` 默认载入 `video-prompt` 业务技能，资源位于 `ruoyi-chat/src/main/resources/short-drama/skills/video-prompt/SKILL.md`；版本进入规划/细化缓存。
- 批次细化保留按场并行和分批策略；内容缺项供审阅，格式错误才重试；不以短模板替换原稿。
- 分镜保存之前再检查，避免先删旧镜头再发现新稿不完整。规则修订不禁止读取或编辑既有薄稿。
- 已审阅单首帧的执行路径同样使用导演规则和详细用户稿；不要因为只传一张首帧而绕过声音、表演与连续性要求。
- 前端 `reviewShot` 合并视频提示词缺项提醒，覆盖可见动作、摄影光色、原对白及发言人；兼容历史时间稿，但不强制新稿列秒段。真实素材 `direct_insert` 不要求生成提示词。

这些是内容结构检查，不等于语义全自动验收或成片质量保证。仍要核对真实关键帧、物件交接、台词在每段的时长，以及实际生成视频的口型、声音和动作。

## 已制作项目的修改

只有提示词需要变化时，只更新 `videoPrompt`，保留镜号、时长、已批准原台词、连续性和图片。留项目快照，通过完整修订接口携带镜头版本并回读，对比图片URL/任务ID。不要为非视觉修订重新生成整套媒体。

当前《甲申逆命》v4依据已完成v3精灵版逐镜重写，25镜仍为180秒；Codex定妆、投影面板与原图片保留。补的是单镜执行信息，不增加查明贪污、追回银钱或扭转战局的结果。提示词同步与内容检查不能声称视频已生成。

## 经验复用与来源

人物选择、对白行动、场景变化与分阶段修订的默认接入见[编剧方法在系统中的接入](screenwriting-methods.md)。按当前人物和事件使用，不套统一故事结构或固定微表情。已制作分镜仅修订描述时保留视频关联；用户明确改画风时同步项目和当前文本方向，旧媒体仍作为历史版本保存。

整集批量制作与后期参照[制作与剪辑经验](../skills/causal-storyboard-production/references/production-editing-lessons.md)。生成任务、摄影镜头、剪辑片段分别记录；共享空间和起止状态后并发，局部失败局部恢复。原片另存，按实际动作与台词落点剪辑，字幕和配乐重新映射到剪辑时间线。该参考同时记录首帧哈希、未知提交查询、字幕对齐与缓存切片的实作问题，使用时按当前接口和项目配置适配。

用户需要首帧时，新增镜头可按指定镜号范围补建关键帧记录，不必重新分析整部剧的道具或重生已有镜头。选择使用首帧时，提交视频前审阅其中的人物数量、精灵与真人相对尺寸、持物手与投影初态；CG尺寸错误先协调参考。未使用首帧的生成流程直接核对已批准资产、构图规划和导演稿。

Seedance 2.5 的输出画质保存在镜头承接 JSON 的 `video_resolution`，前端“输出画质”选择后保存分镜。未填写沿用720p；`1080p-sr` 显式传给上游，不由后端覆盖。根据[Atlas官方参数](https://www.atlascloud.ai/docs/more-models/bytedance/seedance-2.5-reference-to-video/generateVideo)，它使用720p源视频超分至1080p，与原生1080p、ESR分别计费。完成后用实际文件核对分辨率、时长与音轨，不能只看下拉框。

Seedance 2.0 Mini 参考生视频使用完整型号 `bytedance/seedance-2.0-mini/reference-to-video`。分辨率同样来自 `video_resolution`，默认720p，后端显式传递。Mini 的原生分辨率为480p/720p，超分选项为`720p-SR`、`1080p-SR`和`1440p-SR`，不将原生1080p选项套用到Mini。按[官方Mini参数](https://www.atlascloud.ai/docs/zh/more-models/bytedance/seedance-2.0-mini-reference-to-video/generateVideo)安排单镜4—15秒、最多9张参考图与3条参考音频，参考音频合计不超过15秒。项目要求720p时保存该值并核对实际原片，16:9预期为1280×720；教程录屏尺寸单独设置，不从影片分辨率推断。

分辨率合格不等于视觉清晰度合格。交付前从原始视频无损提取 PNG 实帧，在100%尺寸下检查面部、发丝、衣纹、建筑边缘，并结合播放检查运动时的细节与拖影；记录视频码率与文件大小，但不能仅凭码率确定模糊原因。与审阅首帧对照时注明构图和景别变化，不用网页缩略图或二次保存的 JPEG 判断最终清晰度。SR作品若实帧偏软，应明确记录为待改善，不能用1920×1080像素尺寸证明画质已达标。以细节为优先的下一次生成可评估原生1080p，须说明它与1080p SR的区别；没有新增生成授权时，不因审阅意见自动再次付费生成。

用户授权比较不同分辨率时，固定模型、首帧URL及文件哈希、导演提示词、时长、画幅、声音与输出格式，仅改变分辨率参数，每个授权版本提交一次。使用独立候选保存原片与任务ID，避免覆盖原项目已审阅视频或使原合成成片失效。交付原始文件和同显示尺寸的并排播放器，提供全屏或原始像素查看；记录实际尺寸、帧率、时长、码率、文件大小及同步时点的PNG实帧。两次独立生成的动作、表情和构图可能存在随机差异，不将各一次样片视为严格的模型整体排名。

生成的视频使用项目的 `/media/content` 代理加载为本地浏览器音视频对象，可在分镜内播放与下载；保留任务ID，查询进度不重新提交生成。

Seedream 4.7文生图不接图片参考。连续性首帧默认保留人物与场景参考，选该型号时明确报错，不能偷偷换成编辑模型或丢弃参考。用户明确接受纯文字重画候选时，可将该镜承接 JSON 的 `keyframe_reference_mode` 设为 `text_only_candidate`；仅该型号执行此模式，仍加载默认业务规范和所选审美、导演技能，保留原资产与版本核对，但不向上游发送任何人物、场景或道具图片。不宣称已锁脸；需要将此候选用于视频首帧参考时先实际审阅，也可保留候选并关闭首帧参考。候选的服装阶段不自动成为原六集定案。

首帧审阅发现实际起始姿态与原计划不同，且决定接受当前图片时，在视频导演稿增加 `【首帧实况】`，写明实际姿态、持物和左右位置，再相应修订时间节拍。已就绪单首帧的视频路径以该审阅段替代原计划起点，保留原图、任务ID、原计划连续性和默认导演技能；不靠改首帧源字段再重生图片来处理纯表演协调。记录实际图片哈希及接受范围，不能用此段接受未审过的身份或剧情变化。

仓库 `AGENTS.md` 指向本规范。个人Codex技能 `short-drama-video-director` 支持自动发现，集中处理导演提示词和已有素材修订；后端业务技能负责应用内生成，无需用户再复制一遍提示词。

进出门的镜头分别写清摄影机在哪一侧、人物起点、锁闩解除、门扇开合、跨门路线及抵达位置。门向内开或向外开由当前建筑与剧情决定，不能用门扇运动代替人物行进方向。场景母图提供建筑和陈设参考，其机位与人物位置不自动成为动作起点。跨门过程必须能从运动或明确动作匹配点核对，入场完成后再开始屋内事件，后续离场保留自己的剧情触发。

后续剧本正在修改时，允许单独保存原片返修候选：在 `continuity.repair_source_board` 关联原已完成分镜，候选与原镜须属于同一项目和制作剧本，演员形象绑定与场景相同。生成接口核对实际原任务与文件后复用资产，仍执行默认导演审阅和所选技能版本记录；不将项目的后续剧本标为已制作。原镜头和其他已批准素材继续保留，返修用新片段重新剪辑。进出门词法检查仅作审阅提醒，实际运动和声音须另核。

## 固定的可读导演稿格式

新生成和用户要求重写的 video_prompt 使用以下三部分，部分之间及各编号镜头之间空一行。它是可阅读的导演稿，不是逐秒表格；不要套用参考例子的人物、事件、画风或镜头数量。

【起始构图】写本段开始时实际空间、可见人物的身份与必要衣装、相对位置、朝向、姿态、持物和已经发生的动作状态。只有本次确实采用并审阅了首帧，才改用【首帧实况】并以实图为准。角色/场景母图不是已审阅首帧；不能虚构首帧已批准。

镜头1：从起始状态连续展开本段事件，写清景别、机位和一条主要运镜；按动作发起、接触或受阻、可见结果、对手反应推进。原对白逐句注明谁说、对谁说及画内/画外/内心声，安排在真实动作之间。需要有动机的内部切镜时另起镜头2、镜头3；单镜也保留镜头1，不为了格式硬添切镜。同一段只发生同一时空内的连续事件，跨时空另建生成段并记录接点。

当前空间为……。收束段交代此刻的光向、必要材质、环境声与动作声、说话者口型和画外声规则，以及最后确实留在画面中的姿势、位置、手中物和切出点。已经在编号镜头写清的内容不再抄写；只补保证声音与末态可执行的要求。下一段剧情放在 continuity，不提前演出。每部分都应是本段具体内容，不能用通用摄影前缀或几句摘要代替。

原剧情与原对白不因格式调整而删改；时长估算独立存入 timing，正文不列0—2秒等清单。旧人工稿只读、复制或展示时不自动改写；新稿保留真实换行，编辑器不靠视觉折行代替持久段落。

制作与修订要求（revisionNotes）与世界观一起进入原生规划上下文，约束当前分镜范围与资产候选选用；正文仍是剧情和对白依据。修改本版要求会改变场次上下文签名，旧规划不得作为相同配置复现。
